# Methodology — MTN Ghana Data Depletion Sentiment Analysis

## Question
How did public discussion around MTN Ghana’s data-depletion controversy move from subscriber complaints through corporate response, regulatory attention, and later transparency measures?

## Data boundary
The repository describes a public-source analysis using news coverage, public social discussion, regulatory guidance, corporate announcements, and annual-report context. It is not an MTN report, commissioned client work, or a claim that every public reaction was captured.

## Approach
I constructed a dated event timeline, recorded source and platform context, scored sentiment using TextBlob and VADER with contextual manual coding, and summarised reach and sentiment by event type. The source list and event-level labels are visible in the script.

## Outputs
`output/mtn_sentiment_timeline.png`, `output/mtn_media_reach.png`, `output/mtn_sentiment_distribution.png`, and `output/mtn_executive_summary.json` are generated by `scripts/analyze_mtn_sentiment.py`.

## Reproduction
```bash
pip install -r requirements.txt
python scripts/analyze_mtn_sentiment.py
```

## Interpretation and limitations
Sentiment scores are an analytical signal, not a poll of all MTN subscribers. Public reach is estimated from the project’s documented inputs and should be checked against source-level audience data before publication. A timeline can show association between events and discussion; it cannot establish that one intervention caused a sentiment change.
